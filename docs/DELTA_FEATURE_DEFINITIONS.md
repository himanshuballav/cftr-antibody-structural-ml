# Delta Feature Definitions

This document describes how paired Human-versus-Rhesus features are derived for the structural machine-learning workflow.

## Overview

For each antibody clone, the same structural or computational feature is measured separately for the Human complex and the Rhesus complex.

Two paired feature representations are generated:

1. **Signed delta**
2. **Absolute delta**

The signed representation preserves the direction of the species difference. The absolute representation keeps only the magnitude of the difference.

## Signed structural delta

For every paired structural feature:

```text
Delta_Feature = Human_Feature - Rhesus_Feature
```

Example:

```text
Human_Feature  = 12.0
Rhesus_Feature = 8.0

Delta_Feature = 12.0 - 8.0 = +4.0
```

A positive signed delta means the feature value is larger in the Human complex.

```text
Human_Feature  = 7.0
Rhesus_Feature = 11.0

Delta_Feature = 7.0 - 11.0 = -4.0
```

A negative signed delta means the feature value is larger in the Rhesus complex.

## Absolute structural delta

The absolute representation is:

```text
AbsDelta_Feature = abs(Human_Feature - Rhesus_Feature)
```

Using the examples above:

```text
abs(12.0 - 8.0)  = 4.0
abs(7.0 - 11.0)  = 4.0
```

Both therefore have the same absolute delta even though their signed directions are opposite.

## Why keep both representations?

The two models answer related but different questions.

### Signed delta model

Uses:

```text
Delta_*
```

This representation asks whether the **direction** of a Human-versus-Rhesus structural difference is informative for experimental cross-reactivity.

### Absolute delta model

Uses:

```text
AbsDelta_*
```

This representation asks whether the **magnitude** of the Human-versus-Rhesus structural difference is informative, regardless of which species has the larger value.

The signed and absolute feature sets are analyzed separately.

## Where the calculation occurs

The paired structural features are generated by:

```text
07_calculate_paired_deltas.py
```

The output workbook contains separate ML input sheets for signed and absolute features:

```text
ML_Signed_Input
ML_Absolute_Input
```

The signed table contains structural predictors beginning with:

```text
Delta_
```

The absolute table contains structural predictors beginning with:

```text
AbsDelta_
```

## Experimental ELISA deltas

Experimental ELISA summaries use the same directional convention:

```text
Experimental_Delta = Human - Rhesus
```

Examples include differences in maximum OD, mean OD, and log10-dilution AUC.

The ELISA AUC ratio is defined separately as:

```text
Comparison_to_Reference_AUC_Ratio
    = Rhesus_Log10_AUC / Human_Log10_AUC
```

for the current Human-versus-Rhesus project.

These ELISA-derived variables describe or define the experimental phenotype. They are **not used as structural ML predictors**.

To make this separation explicit in the final ML-ready workbook, ELISA-derived delta columns are namespaced as experimental variables, for example:

```text
Experimental_Delta_Log10_AUC
Experimental_Delta_Max_OD
Experimental_Delta_Mean_OD
```

## Target leakage protection

The binary target is:

```text
Cross_Reactive_Target
0 = non-cross-reactive / reference-specific
1 = cross-reactive
```

If this target is derived from ELISA measurements, ELISA OD, AUC, delta-AUC, AUC-ratio, threshold, and related phenotype variables must not enter the predictor matrix.

The ML scripts therefore use only:

```text
Signed analysis:   Delta_* structural features
Absolute analysis: AbsDelta_* structural features
```

## Reproducibility rule

Human and Rhesus values must correspond to the same antibody clone and the same underlying feature before a paired delta is calculated.

The analysis should not mix measurements from different clones, different feature definitions, or unmatched structural conditions.
